## 原厂锐度请求

精确目标是 ILCE-7M3 4.04，内部版本 `37114_13.2026020901`。`viewUnified2.so` 原始 SHA-256 为 `f561a1e5fa0d10d55727dd4a10ced97c9613b698a40b489ff9317634485e5129`，`libbackup.so` 为 `b6420f8f7cacade524e1ba7c5b0d8b06691c22ed793dca084fdf1c1d9ae092f3`。

原始创意风格 setter 位于 view 库偏移 `0x420d18`，会修改整个配方和保存槽。新适配器 `payloads/a7-fl-sharpness-native.c` 只构造一个参数：

- 原厂 `Param<int>`：ID 392，值 −3…+3。
- 原厂请求目标 `@M00B`，动作 38。
- 分配和对象所有权转交遵循原始 setter；不调用 Backup 写接口。
- 返回 1 **只代表调用已发出**。原厂请求的返回寄存器不是已证实的成功标志，不能据此显示「完成」。

`research/sharpness_probe.py` 默认离线构建；只有 `--live` 才访问 USB。真机实验先校验机型、版本、完整已安装加载器及 r3 模块，保存完整设置快照，再逐次绑定代码字节及当前属性。请求后由另一条读取路径检查实际活动值，最后恢复原值。

本轮真机原状态为中性、第三风格槽、对比度 +1、饱和度 −1、锐度 −1。共检查 9 个字节属性：活动风格与三个活动参数、选中槽、三个槽内参数、槽内风格。

| 实验 | 活动锐度 `0x0107018a` | 槽内锐度 `0x01070a1d` | 其他 7 项 |
|---|---|---|---|
| 原始完整 setter：−3 / +3 | 253 / 3 | 253 / 3 | 保持原值 |
| 单参数请求：−3 / +3 | 253 / 3 | 255 / 255 | 保持原值 |
| 每轮结束恢复 | 255，即 −1 | 255，即 −1 | 全部与原状态一致 |

完整 setter 记录在私有 `.lab/sharpness-probe/1794392492648318000/`；单参数记录在 `.lab/sharpness-probe/1794392832978275000/`。这些只证明参数路径和恢复，不证明成片效果。实验后适配器改为忽略不明返回值；这个修改已重新完成离线 ARM 测试，未重新做真机往返，不能把旧负载日志当成新二进制的硬件认证。

进一步静态追踪发现 libObj 将锐度消息打包为 AV-CAM 控制 `0x403c`，接收者复制到内部锐度字段。另一个 `0x40f4` 控制调节 SharpnessGain。后者不是已确认的锐度范围或清晰度接口。AV-CAM 文件偏移与运行地址属于另一地址空间，不可直接当作 Linux 进程指针写入。

## 独立空间算法

`payloads/a7-fl-spatial.c` 接收独立的 8 位亮度平面，输出另一平面；没有访问机身缓冲区，没有调用 Sony ISP。算法是本项目自制近似，不能称为 A7 IV 原厂 FL 算法。

- 锐度 −3…+3：原像素与小半径均值的差，按有符号强度加回；0 为不锐化。
- 锐度范围 1…5：分别对应半径 5…1，数值越大处理越细；锐度为 0 时这项不产生影响。
- 清晰度 0…9：半径 16 的局部对比度，使用中间调权重，单像素改变量限制在 ±24。
- 两项都为零时逐像素保持亮度；恒定区域保持不变，边界使用复制扩展。
- 使用滚动行和累计值，复杂度随像素数线性增长；没有堆分配或浮点。工作区为 `70 × 宽度` 字节，6000 像素宽需要 420,000 字节，另外仍需输入和输出图像内存。
- 拒绝参数越界、尺寸/跨度不合法、长度不足、工作区未对齐及不允许的缓冲区重叠。

独立测试使用慢速二维卷积作为参考，覆盖 5 种尺寸、7 种图案及全部 350 组参数，共 12,250 个案例。Mac 运行 ASan/UBSan；相同 C 源码编译成 ARM，在 QEMU 中运行并逐像素核对。该测试不能说明机身处理速度、颜色空间正确性或拍摄稳定性。

## 复现

需要 Mac Clang、ARM GNU 工具链和 `qemu-system-arm`：

```sh
python3 research/native_spatial_test.py
python3 research/sharpness_request_test.py
# 使用用户本机的原厂文件；此命令不接触 USB
python3 research/sharpness_probe.py \
  --usr "$A7M3_FIRMWARE_ROOT/0700_part_image/dev/nflasha15_unpacked" \
  --model-only
```

前两项只使用本项目源码。锐度适配器的 QEMU 测试覆盖合法范围、非法值、两次分配失败及单参数请求结构；原厂 setter 夹具另外覆盖 38,416 组组合。输出、输入散列及真实实验记录位于 `.lab/`，不提交 Sony 二进制或相机备份。

## 临时图像元数据探针

进一步找到 `dataflowInfraFramework.so` 的 `C_DataflowInfra_StdData_YC::GetEntry_ImageSizeInfo`（偏移 `0x22300`，Thumb），以及 `libObj.so` 导入槽 `0x126ce20`。原厂 `GetData_All` 复制对象偏移 20 开始的 60 字节，标量访问器包含有效图像尺寸、DMM 句柄、压缩、排列、位深枚举及条带宽度。**这些字段的存在不代表已经取得像素，也不代表处理时拥有图像缓冲区。**

`research/yc_trace.py` 构建临时 RAM 探针：仅在精确库身份和原导入槽匹配时，将该槽指向保留在匿名内存中的记录包装函数。包装函数调用原函数一次、保留返回值，只复制成功返回的元数据；不做图像写入、文件 I/O、分配或等待。v1 最多记录 128 项，仅收集有效尺寸至少 2800×1800 的候选；该过滤现已由下述 v2 的独立最大样本槽替代。

ARM 包装函数通过 2,080 组测试，覆盖原函数失败、禁用、锁已占用、容量达到/超过上限、小尺寸跳过、结果和元数据一致性及数组边界。安装器只修改进程中的一个已核对导入槽，不改系统文件。停止时恢复原槽，保留匿名分配直到进程退出，避免已进入包装函数的调用访问被释放内存。

`research/yc_metadata_fixture.py` 另行提取原厂 25 个标量访问器和 60 字节整块访问器，在 QEMU 中使用 256 种已知字节模式，完成 431,616 项检查，核对 Python 解析器的字段偏移、长度和输出边界。枚举的实际含义及真实帧内容仍未验证。

v1 探针曾成功加载，记录在私有 `.lab/yc-trace/1794394519470077000/`。用户保持开机拍摄并回放大尺寸 JPEG 后，已读取并解除探针：`status=2, armed=0, count=0, dropped=0`，见 `.lab/yc-trace/1794396814049091000/`。这只说明没有符合 v1 尺寸过滤条件的记录，不能区分接口未被调用、调用失败或尺寸条件不匹配。原导入槽已经恢复；没有写入新的功能固件。v1 源码位于提交 `63f3951`。

v2 已增加调用/失败计数，取消小图像过滤，保留前 127 份成功记录，并用独立槽保存最大有效尺寸的样本，避免早期预览占满后漏掉照片。记录器不等待竞争中的锁，因此计数不包含未取得锁的并发调用。另新增 JPEG 编码入口记录器：观察 `libObj.so` 导入槽 `0x126b17c`，目标为 `libmpr.so` 偏移 `0x85ecbc` 的 `MprIf::EncodeStill`；只复制原调用的 64 字节 RegionInfo，不解引用其中的物理像素地址。

v2 两种模式通过 4,128 组 ARM 检查，包含原函数失败时不可访问的参数指针、原返回值、两种对象布局、容量边界和最大样本槽。安装前会先检查两处原始导入槽，再逐项附加；停止先禁用记录，取得记录锁后才恢复槽，避免繁忙时丢失探针位置。新版不会接管未知版本的旧探针。

两次加载 v2 的尝试均停在 USB 维护模式切换前，尚未执行相机内负载。后续分阶段诊断确认 USB 配置读取、接口获取、传输恢复和 SCSI INQUIRY 均正常，卡在 `SonyExtCmdCamera.getCameraInfo()`，18 秒进程超时；原切换脚本为 25 秒超时。已请求用户断电重启恢复，当前没有活动的本项目跟踪探针，也未更改 r3 系统模块。

离线构建默认不接触相机。下面的 `--live` 命令用于已配置的 USB 交接环境；安装到停止之间保持相机开机，不能把它当作持久固件更新：

```sh
python3 research/yc_trace.py --usr "$A7M3_USR" --kind both
python3 research/yc_metadata_fixture.py --usr "$A7M3_USR"
python3 research/yc_trace.py --usr "$A7M3_USR" --kind both --live --action install
# 保持开机、拔 USB，正常拍照，然后重新连接。
python3 research/yc_trace.py --usr "$A7M3_USR" --kind both --live --action stop
```

另一个候选为 `libmpr.so` 的 `MprIf::EncodeStill`，`libObj.so` 内存在两处调用，其中一处邻近 `ObjConverter`。尚未观察正常按快门是否经过该编码入口，不能据函数名称就注入照片处理算法。
