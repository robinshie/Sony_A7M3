# FL 方向：A7M3 4.04 机内色彩接口研究

2026-11-11。已离线执行原厂扩展 Gamma 消息打包函数、AV-CAM 接收函数和一个原厂一维曲线采样器。**采样器的 1025 节点格式已确认，但扩展指针到该采样器的连接、地址空间与最终照片输出尚未确认。** 已有 [FL 近似桌面算法](fl-look.md)，尚未向机身接入或烧录 FL。

Sony A7 IV 的 [Creative Look 帮助指南](https://helpguide.sony.net/ilc/2110/v1/en/contents/TP1000640837.html) 列出八个可调项目，并描述 FL 的色彩和对比特征。该指南没有给出可移植到 A7M3 的 FL LUT、算法或内部实现。后续自制效果应标为近似实验效果；此处也不假设 Sony FL 内部必然使用 3D LUT。

## 本轮结论与证据等级

| 结论 | 证据 | 边界 |
| --- | --- | --- |
| 4.04 存在扩展 Gamma 开关、照片效果 Gamma 模式和表指针参数 | 原厂错误字符串、参数请求及机器码 | 名称不说明表的维数、颜色空间或内存布局 |
| 两个输入消息 ID 被接受，参数被打包为 14 字节控制消息 | 原厂 ARM 函数及公共转换器在 QEMU 中通过 154 项检查 | ObjMsg、Param 与日志边界由测试替身提供 |
| 对应序列将 14 字节送入 OSAL 消息队列 | 静态调用链，含明确的 `SeqSetExGammaTableControl` 错误文字 | 尚未联机验证消息收发、ISP 应用结果或实拍 |
| AV-CAM 注册表把 `0x40f0` 指向一个参数接收函数 | 注册表精确值检查，原厂接收函数通过 2560 组 QEMU 检查 | 两端尚未联机运行；接收成功不等于曲线被应用 |
| AV-CAM 存在 1025×uint16 → 96×uint32 曲线采样器 | 原厂采样器、插值和除法共 1,049,088 次输出比较通过 | 已确认此函数格式，不能据此认定扩展指针接受相同格式 |
| 表地址仅作为 32 位数复制 | QEMU 用 0、1、普通值和高位值测试通过 | 打包函数不校验、不读取表内容，成功返回不代表地址可用 |
| 另有 Monitor LUT 相关路径 | `SequenceAppSetMonitorLutCmd`、`MSG_ID_VDF_DISP_SET_MONITOR_LUT` 字符串 | 不能与最终 JPEG 的色彩处理混为一谈 |

本轮只对 Gamma 接口做本地静态分析与离线 QEMU 执行，没有向相机发送扩展 Gamma 命令、传入新表地址或修改图像处理。同期写入的 RW 图标修复是独立的 UI 改动。

## 固定版本与可复现测试

输入为用户本地解包的 `/usr/lib/libObj.so`，SHA-256：

```text
1117453a969c9dedeb9bf6b006514fd9c2644a79085590a797189df109d64d23
```

安装 ARM GNU 工具链和 QEMU 后，只需运行：

```sh
python3 research/gamma_interface.py --usr \
  "$A7M3_FIRMWARE_ROOT/0700_part_image/dev/nflasha15_unpacked"
```

脚本从本地原厂库提取 `0x00ab69c4` 至 `0x00ab6aef` 的 300 字节，以及公共转换器 `0x00aced80–0x00ad0033` 和原始 GOT 表，保留原虚拟地址、分支和字面量。测试运行在无网络、无 USB 的 ARM QEMU；仅替换 `ObjMsg::GetMessageId`、`GetParam`、`Param<int>::GetValue` 和错误日志函数。原始字节、ELF、日志与散列证明保存在忽略目录 `.lab/gamma-interface/`，不发布 Sony 二进制。

预期标记：`QEMU_GAMMA_INTERFACE_PASSED 154 cases`。77 组检查分别经直接入口及原厂 `0x40f0` 派发执行，覆盖两种接受消息、两个开关的所有有效组合、五类指针值、七种缺失参数掩码、非法枚举、七种无关消息，以及输出前后保护字节。证明文件明确保留 `table_format_known=false`、`output_path_known=false`、`flash_ready=false`。

## 已确认的调用约定

原始 Thumb 入口 `0x00ab69c5` 的寄存器参数为：`r0=消息对象`、`r1=输出缓冲区`、`r2=32 位序列字段`。这里的地址是固件 ELF 虚拟地址，不是可直接用于真机的进程绝对地址。

接受的消息 ID：`0x75e6`、`0x76ac`。非法消息返回 4；合法输入返回 0。尚未将这两个数字全部关联到消息枚举名称，不能混用下游控制编号。

| 参数 ID | 由原厂错误文字确认的名称 | 已验证编码 |
| --- | --- | --- |
| `0x9a18` | `PARAMID_EX_GAMMA_TABLE_SW` | `0x4da → 0`，`0x4db → 1` |
| `0x9a19` | `PARAMID_PICTURE_EFFECT_GAMMA_MODE` | `0x4dc → 0`，`0x4dd → 1` |
| `0x9a1a` | `PARAMID_EX_GAMMA_TABLE_POINTER` | 按 32 位小端原样复制 |

| 消息偏移 | 长度 | 行为 |
| --- | --- | --- |
| 0 | 1 | 写入 `05` |
| 1 | 1 | 本函数不写入；静态观察到调用者先清零整个消息 |
| 2–3 | 2 | 写入 `f0 40`，下游控制编号 `0x40f0` |
| 4–7 | 4 | 第三个参数按小端复制；实际语义仍需下游确认 |
| 8 | 1 | 扩展 Gamma 开关编码 |
| 9 | 1 | 照片效果 Gamma 模式编码 |
| 10–13 | 4 | 表指针值，原样复制 |

缺失参数和非法枚举返回 4，但可能已经改写部分输出字段。调用方必须丢弃失败结果。打包函数不验证表地址的对齐、可访问性、大小或地址空间。

## 静态调用链与继续追踪点

下列位置均属于散列匹配的 `libObj.so`；目前对公共转换器和打包函数进行了执行测试，序列及队列发送仍为静态观察。

- `0x00b12090` 序列入口：错误文字为 `SeqSetExGammaTableControl`；`0x00b120c6` 清零长度为 14，`0x00b120d4` 传入控制编号 `0x40f0`，`0x00b120d8` 调用公共转换器 `0x00aced80`。
- 公共转换器使用 GOT `0x0126ae58 + 0x3c64 = 0x0126eabc` 中的指针 `0x00ab69c5`。QEMU 保留原始间接派发，确认 `0x40f0` 到达扩展 Gamma 打包函数。
- `0x00b120e4` 指定发送长度 14，`0x00b120ea` 调用发送封装 `0x00b10c84`。
- 发送封装调用 `osal_valloc_msg_wait` 分配消息，再复制消息数据，最后在 `0x00b10cf8` 调用 `osal_snd_msg`。这段代码本身也没有读取表地址指向的内容。
- 初始化路径在 `0x00a3baf0` / `0x00a3bafe` 为表指针注册零值，`0x00a3bb3c` / `0x00a3bb4c` 为开关注册 `0x4da`；`0x00a408fe` / `0x00a4090c` 为照片效果 Gamma 模式注册 `0x4dc`。这些是静态默认值，不代表当前机身状态。

这部分原有打包测试仍保留 `table_format_known=false`；新发现和执行证据由独立的 `gamma-avcam/proof.json` 记录，避免把两种测试合并成端到端验证。

## AV-CAM 接收者与一维曲线（新增）

输入为 `0700_part_image/dev/nflasha3_unpacked/av-cam.bin`，18,449,784 字节，SHA-256：

```text
e1b0f84e8323005a34b43de6dd0083fca712d2c654f0d9716512e0a54631bbe7
```

以下均为该二进制的**文件偏移**。基址 `0x635c6000` 与其 ORIL 头和绝对函数指针一致；它不是可以传给 Linux 进程的通用地址。

| 文件偏移 | 静态观察 / 已执行验证 |
| --- | --- |
| `0x1174a20` | 四个 u32 为 `40f0, 63be1235, 0, 63be9d4d`，关联接收函数与参数检查函数 |
| `0x61b234` | 原厂接收函数；从消息字节 8、9、10–13 读出两个开关与小端 32 位指针，保存到状态块 `0x1039774 + 0x2bc/0x2c0/0x2c4`，返回 1 |
| `0x623d4c` | 参数检查路径；比较状态和请求值并记录差异，未发现表长度或内存验证 |
| `0x5e797a` 附近 | 将来源结构的 `+0x2bc/0x2c0/0x2c4` 转移到成像参数结构 `+0x6e4/0x6e8/0x6ec`，根据开关和非零指针设置状态字节；仅静态观察 |
| `0x7f89dc` | 将成像参数写入后续参数块；`0x7f8a54` 复制 `+0x6ec` 指针到另一个输出结构 `+8`，仍不读取曲线 |
| `0x7f8aae` | 独立的一维采样器，原厂机器码已在 QEMU 执行 |
| `0x7f8a82` / `0x19f40` | 采样器所调用的整数插值 / 无符号除法，均执行原厂机器码 |
| `0x8b5f52` | 1025 个 u16 的原厂恒等节点：`min(i*64, 65535)`；由本地固件提取并逐项检查 |
| `0x5e8616` | 一个已找到的采样器调用点；选择原厂对比度 / 照片效果表，**尚未证明此处使用扩展指针** |

原厂接收函数对 0–255 的开关值都照抄，亦不解引用表指针。离线试验覆盖两个日志分支、五类指针值以及状态块的写入边界；这里只在完整 14 字节输入下执行，不代表短消息安全。

### 已确认的采样器格式

- 参数：`r0=&u16模式`、`r1=96×u32输出`、`r2=96×u16输入采样值`、`r3=1025×u16曲线节点`。
- 对每个输入 `x`，取 `i=x>>6`，读取 `T[i]` 与 `T[i+1]`。节点横坐标为 `i*64`，末节点横坐标为 **65536**。
- 插值计算为 `T[i] + (((x&63)*(T[i+1]-T[i])+32)/64)`，使用原厂无符号除法。当前生成器只接受单调非降曲线；不将下降曲线解释成受支持格式。
- 模式等于 1 时保留插值结果；其他模式右移 6 位、按第 5 位取整并限制正常单调曲线的结果不超过 1023。
- 原厂恒等节点最后一个值饱和为 65535。因此输入 65535 经插值得到 65534；不能假定这张表在每个 16 位码值都严格恒等。
- 格式不带长度、通道、色彩空间等元数据；仅此函数需要至少 2050 字节的输入表。不推断相机端完整分配大小或缓存要求。

另有 `0x56a09c` 的 96-u16 Gamma 加载器，检查输入描述符的长度必须为 96，然后复制并做地址转换；调用链还包括 `0x55e304`、`0x612da0`、`0x7fdd92 → 0x5e80bc`。这是不同的表层级，尚未把它与扩展消息连接起来，未纳入本轮执行证明。

### 一条命令复现 AV-CAM 测试

```sh
python3 research/gamma_avcam.py --avcam \
  "$A7M3_FIRMWARE_ROOT/0700_part_image/dev/nflasha3_unpacked/av-cam.bin"
```

输出 `QEMU_AVCAM_GAMMA_PASSED`：2560 组接收检查和 1,049,088 次采样比较。覆盖全部 65,536 个 u16 输入值，四种模式（0、1、2、65535），四种单调曲线（原厂恒等、二次曲线、常数、实验 FL 明暗曲线），每次检查输出边界。四组的尾块用 65535 填充，所以比较次数略大于 `65536×16`。

脚本固定固件散列，在 QEMU `virt` 内存中保留原厂加载地址与机器码。唯一可达的替换调用是日志；除零路径设为失败陷阱且不应触发。输出 `.lab/gamma-avcam/proof.json` 记录固件、源码、候选明暗表和日志散列，保留 `external_pointer_to_sampler_proven=false`、`pointer_address_space_known=false`、`jpeg_output_proven=false`、`flash_ready=false`。这不是相机整机或 ISP 仿真，也不是完整 RGB LUT 在 ARM 上的验证。

## 下一步接入条件

1. 继续跟踪 `0x7f89dc` 输出结构 `+8` 的消费者，确认扩展指针最终在哪个处理器、哪段代码中被读取。当前已找到控制编号对应接收者，尚未闭合队列运行和像素处理链。
2. 找到非零表指针的生成者、分配者和释放者，确认地址是进程虚拟地址、共享内存地址、物理地址还是句柄。只读记录地址及映射，尚不解引用未知长度区域。
3. 对扩展接口本身确定表长度、元素位宽、通道排列、输入输出编码、所有权、生命周期和缓存同步要求。独立采样器的 1025-u16 格式只解决其中一个候选函数，仍未发现可直接导入桌面 3D LUT 的证据。
4. 分别确认对预览、照片效果、JPEG、视频、回放的作用。接口名字含 Gamma 或 LUT，均不能代替照片输出验证。
5. 有了有效原厂表及明确长度后，先做只读导出与原样重载实验，再测试恒等表。之后才考虑可逆的 RAM 色彩变换和实拍比对。

暂时没有依据把 `.cube` 文本、任意 RGB 数组或主机进程地址直接交给这个接口。下一次开发从以上派发关系和指针来源继续，无需重做图标或菜单入口。
