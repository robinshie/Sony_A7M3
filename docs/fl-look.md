# FL Inspired v0：本地算法与快速验证

2026-11-11。已实现桌面实验算法、3D LUT 导出和独立 QEMU 模型中的 FL 菜单及 RGB 色彩预览；原厂一维采样器也已在隔离测试中处理过它的明暗曲线。同日另行实现并加载了[由 Mac 开关的真机 FL 近似试用表](native-fl.md)，回读通过；尚无真机 FL 菜单和八项调节，成片及重启保存待验收。它是本项目自制的近似效果，没有 Sony FL LUT 或 A7 IV 对照实拍，不能标为原版 FL。

## 启动可操作的 QEMU 模拟

设置已有的 `A7M3_FIRMWARE_ROOT` 后运行：

```sh
python3 ui/play-fl.py --qemu /path/to/qemu-system-arm
```

这会重新构建并打开 FL 模拟界面。Mac 可指定本地已经修复 Retina 缩放的 QEMU；省略 `--qemu` 时使用 `A7M3_QEMU` 或 PATH。无需连接相机。

新增位置为 **MENU → 拍摄设置 1 → 第 12 页 → 创意外观 → FL（实验版）**。「创意外观」与「创意风格」是并排的同级项目，FL 不在创意风格列表里。原有 13 个风格及复古衣橱保留在原来的创意风格中。

Fn 也分别提供「风格」和「外观」两个格子（第 11、12 格）；原先第 12 格的照片效果仍可从 MENU 进入。新增菜单行使色彩页拆成两页，图片配置文件保留在第 13 页；FL 模型共 39 页，普通模型仍为 38 页。

选中 FL 后显示标准 / FL 合成色彩图及八项调节。左右选择项目，上下修改数值；C 或 Delete 重置本次编辑，Enter 确认，Esc 取消本次编辑（包括尚未确认的重置）。确认后返回 Fn，再按 Esc 可看模拟取景。「创意外观 → 关」恢复先前的创意风格及参数；在创意风格里重新选择标准或复古衣橱，也会关闭外观。外观生效时，原创意风格主菜单行显示「外观优先」，原选择仍被保存。

功能命名和层级参考 [Sony A7 IV 创意外观说明](https://service.sony.com.cn/Enjoyment/ILCE-7M4/02.html)：其原机入口位于「曝光/颜色 → 颜色/色调 → 创意外观」。本项目保留 A7M3 菜单框架，并新增同级项目；目前外观内只有「关 / FL（实验版）」，八项调节使用本项目自己的模拟算法，不是原厂算法移植。对比页是实验工具页面，不是原厂菜单截图。相机成像、实时性能和保存照片仍未模拟。

### 八项调节与作用

项目及范围依据 [A7 IV 官方帮助指南](https://helpguide.sony.net/ilc/2110/v1/zh-cn/contents/TP1000651009.html)。下面的具体处理方式是本项目定义的实验模型，作用于基础 FL RGB LUT 之后的编码 sRGB 像素。

| 项目 | 范围 | 本模型的处理方式 |
| --- | --- | --- |
| 对比度 | −9～+9 | 围绕码值 128 调整斜率 |
| 高光 | −9～+9 | 按亮度平方加权调整亮区 |
| 阴影 | −9～+9 | 按反向亮度平方加权调整暗区 |
| 褪色 | 0～9 | 抬升黑位并压缩明暗范围 |
| 饱和度 | −9～+9 | 围绕加权亮度缩放颜色差异 |
| 锐度 | 0～9 | 3 为本模型中性；小于 3 柔化，大于 3 增强轮廓 |
| 锐度范围 | 1～5 | 数值越高，空间滤波半径越小，作用于更细的轮廓 |
| 清晰度 | 0～9 | 用更大半径的亮度差分增强局部对比 |

初值为 `0,0,0,0,0,3,3,0`，是本模型的中性增量设置，**不是从 A7 IV 提取的 FL 默认配方**。所有额外调节在这组值下不改变原有 FL LUT 的输出。调节后名称旁显示 `*`；关闭外观再打开仍保留已确认数值。设置只保存在当前 QEMU 运行内存里，关闭并重启模拟器会恢复初值。模拟录像中锐度范围不可改。

预览底部的细纹区用于观察锐度、锐度范围和清晰度；这三项经过实际空间滤波，无法放入普通逐像素 3D LUT。`research/fl_look.py` 的桌面导出仍只导出基础 FL 配方，**不会自动读取 QEMU 中修改的八个值**。

新增代码位置：

- `ui/ui.c`：列表入口、对比页、选择/取消与模拟取景处理。
- `ui/fl_assets.py`：从同一份 FL 配方生成 33³、RGB u16 查找表和测试向量。
- `ui/fl_lut.h`：ARM 端整数三线性插值；画面颜色在 QEMU 内实际运算，未使用预渲染的 FL 对比图替代算法。
- `ui/fl_adjust.h`：八项调节、亮度处理、边缘复制的可分离模糊与细节增强；按画面范围处理，不改变菜单文字。
- `ui/verify-fl.py`：512 个 ARM/桌面参考向量、7 个实际帧缓冲色块，以及同级入口、Fn/MENU、取消、重新定位、复古衣橱参数保留和图片配置文件互斥验证，均已通过。
- `ui/verify-fl-adjust.py`：八项数值上下限、每项对右侧预览像素的作用、左侧标准图保持一致、确认/取消/重置/再次进入及视频状态限制，均已通过。
- `ui/test_fl_adjust.c`：与 ARM 相同的算法代码在宿主 ASan/UBSan 下通过；包含 48 组独立二维卷积对照、单行/单列边界、完整 LCD 尺寸及带行间距的缓冲区检查。

显示仍为 640×480。QEMU 模型不会把任何菜单或 LUT 写入真机；原厂 AV-CAM 测试与此自编 RGB 内核是两个独立的验证对象。

## 改一次配方，快速生成

在仓库根目录运行，沿用项目的 Python/Pillow 环境：

```sh
python3 research/fl_look.py build
```

修改 `recipes/fl-inspired-v0.json` 后重复命令即可，默认输出 `.lab/fl-v0/`：

| 文件 | 用途 |
| --- | --- |
| `fl-inspired.cube` | 完整 RGB 变换，默认 33³ 节点，可选 `--size 17/33/65` |
| `tone-u16le-1025.bin` | 只有标量明暗曲线，供离线原厂采样器实验；不含矩阵和色相调整，不是烧录包 |
| `recipe.json` | 本次参数快照 |
| `proof.json` | 输入输出空间、插值、源代码及产物散列，明确机内接入和烧录状态为 false |

对已经解码为 sRGB 的 JPEG/PNG 做前后对比：

```sh
python3 research/fl_look.py preview \
  --input /absolute/path/photo.jpg \
  --out .lab/fl-photo
```

有 ICC 时先转换为 sRGB；无 ICC 时拒绝猜测，确认像素已是 sRGB 后加 `--assume-srgb`。输出 `fl-preview.png`、`comparison.png`，均嵌入 sRGB ICC。保留输入文件，不复制原图 EXIF；这不是 RAW 解码器，不可直接输入 ARW、S-Log 或 HLG。预览支持 8 位 RGB 图像。

## 算法顺序和调节项

输入输出均为显示用途的 sRGB，归一化 0–1，D65。先执行 sRGB 逆传递函数，在线性 RGB 中应用曝光和 3×3 矩阵，再限制到 0–1 并重新编码 sRGB。矩阵每行和为 1，使中性灰保持中性；超出范围的颜色在这里裁切。

随后在编码后的 RGB 上做 HSV 色相与饱和度调整。三条平滑色相权重分别面向橙色、绿色、蓝色区域；它们只是颜色范围选择，不识别人脸、衣物或天空。初版整体降低饱和度，绿色向青色微调，橙色区域减弱去饱和的程度。最后按每个 RGB 通道应用单调分段线性曲线：轻抬黑位、增强中间调对比、收住最亮端。

`strength` 在编码后的 sRGB 中混合原始和处理结果；为 0 时参考算法逐值恒等。配置中的 `exposure_ev`、`linear_matrix`、`saturation`、`hue_bands`、`tone_curve` 是独立参数。没有调用机身的对比度、饱和度、锐度三个设置。桌面基础配方不含空间颗粒、光晕或锐化；QEMU 另外实现了上一节中的空间调节。

完整变换采样成 RGB 3D LUT；导出顺序为红最快、绿其次、蓝最慢，符合 [Adobe Cube 1.0 规格（镜像）](https://kono.phpage.fr/images/a/a1/Adobe-cube-lut-specification-1.0.pdf)。图片预览使用 [Pillow Color3DLUT](https://pillow.readthedocs.io/en/stable/reference/ImageFilter.html#PIL.ImageFilter.Color3DLUT) 的三线性插值，测试另有独立三线性参考计算。

## 本轮验证

```sh
python3 -m unittest discover -s research -p test_fl_look.py -v
python3 research/gamma_avcam.py --avcam \
  "$A7M3_FIRMWARE_ROOT/0700_part_image/dev/nflasha3_unpacked/av-cam.bin"
```

8 项桌面测试通过：sRGB 传递函数往返、灰阶单调与中性、强度零时恒等、错误参数拒绝、Cube 通道顺序、端点、插值、可重复构建、原厂格式表长度与单调性，以及图像 ICC / 输出尺寸。33³ LUT 相对浮点直接计算，在固定种子的 6000 个 RGB 输入上，归一化通道最大误差为 `0.01751823`，RMS 为 `0.00108709`；这是采样集误差，不是全色域上界。Pillow 与独立三线性计算差异不超过 1 个 8 位码值。

AV-CAM 测试运行原厂接收、采样、插值和除法机器码，包含本配方的 1025 节点明暗表。2560 组接收检查和 1,049,088 次采样比较通过。其证明范围见 [机内接口研究](color-interface.md)：只确认原厂函数能处理这份标量表，**没有把整个 3D LUT 交给相机，也没有证明最终 JPEG 被改变**。

当前仅用合成灰阶、色相渐变及色块验证生成和预览流程，还没有实拍效果验收。下一步机内工作是查明扩展 Gamma 指针的消费者、内存约定和照片路径，并寻找颜色矩阵或多维颜色表入口；单独一条 Gamma 曲线无法承载本算法的全部 RGB 色彩变化。
