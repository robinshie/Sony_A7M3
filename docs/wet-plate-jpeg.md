# 湿版黑白 JPEG 拍后处理

本功能在 A7M3 4.04 的现有「创意外观」中加入独立 FL7 湿版黑白，并为原 FL～FL6 及 SD 导入的独立风格提供「湿版黑白（拍后）」开关。原有风格首次升级默认关闭，保留配色、曲线、颗粒、光晕、暗角和删除状态。FL7 的黑白处理固定开启，可以调整其它参数；删除后不会在每次开机重新出现。

这是高反差、偏蓝感光权重的数字黑白效果，并非化学湿版摄影的完整模拟。只改 JPEG 编码前的像素，不要求实时取景变黑白，也不修改 RAW。

## 使用

进入 MENU → 拍摄设置 1 → 第 14 页 → 创意外观，在风格列表中选择 FL7 湿版黑白，点第 4 页「保存 → 确认」。第 3 页末尾是「湿版黑白（拍后）」；其它风格可以独立开关，FL7 固定开。删除入口移到第 5 页；同级 SD 导入入口保留。

目前实际验证范围为全画幅、3:2、JPEG L（6000×4000）、M（3936×2624）、S（3008×2000）。拍照后等待存取灯熄灭再拍下一张。湿版处理需要额外时间；有颗粒、光晕等效果时耗时叠加。其它比例、裁切、连拍及视频未由本轮验证覆盖。

## 处理和保存

沿用已验证的拍后图像占用与缓存同步流程，在颗粒、光晕、暗角之后，对实际 UYVY 源帧逐像素处理，再交回原厂缩放/JPEG 编码。黑白亮度使用 10% 红、32% 绿、58% 蓝权重和固定高反差分段曲线，色度归中性。M/S 使用实际源画布与输出尺寸，保持行间填充区域不变。

现有六套 A7FL 设置记录仍是 schema 6、128 字节；黑白开关放入独立 A7CU 双槽，升级为 schema 3，文件长度仍为 2848 字节。启动时仅追加一次 FL7，保留已有独立风格及当前选中状态。旧模块不能读取 schema 3；回退时必须使用安装前配套配置备份，不能只换旧模块。

现有 `.a7look` 导入格式仍是 A7FL-LOOK/1，未扩展黑白开关的文件语法；导入风格默认关，可在机内设置并保存。

## 构建和验证

实现位于 `payloads/a7-wet-plate.h`、`payloads/a7-fl-module.c`、独立配方库及 `research/kernel_probe/capture_wet.c`。私有原厂文件、照片和相机备份仅保存在忽略提交的 `.lab/`。

1. 用 `research/capture_kernel_probe.py build --route wet` 构建专用内核，保留图像尺寸、占用和缓存检查。与旧临时模块使用不同回调标识。
2. 内核临时自检与控制桥验证后，实拍 L/M/S。`capture_wet_fetch.py` 核对同一帧处理前后样本，`capture_wet_jpeg_test.py` 核对下载 JPEG 的尺寸、全图中性色度与源亮度抽样。
3. `native_wet_integration_test.py --kernel <同一内核目录>` 编译包含该内核的完整模块，并运行原厂 ARM 菜单节点、开关、保存和冷启动恢复测试。它不等同于真机按钮/显示验收。
4. `native_wet_finalize.py --bridge <真机控制桥证明> --catalog-snapshot <安装前只读配方目录>` 校验全部源文件和产物散列，测试现有库保留和 FL7 追加，仅在真实 JPEG 证据通过后允许绑定。
5. 通过当前精确前像的更新核心及主机故障测试后，`deploy_wet_plate.py` 生成私有候选。安装顺序为简中语言、英文语言、功能模块，每个文件独立预检、备份、写入、完整回读；安装时保留四份原配置和两份独立库。
6. 安装后彻底断电，再验收机内菜单、开关、JPEG 和保存恢复。未完成这一步时不覆盖稳定 v0.01 发布附件。

内部更新编号用于限制前像和日志，不是独立公开 r 版本。该升级路径仅用于已经安装创意外观、且当前模块 SHA-256 为 `30474345352eaed6b1feb8f33e389278febaeb6c3fc493dc2355ab560ca591a4` 的本机；不是纯原厂 4.04 首装工具。

## 本机实测进度（2026-11-18）

同一内核的 L/M/S 实拍源样本及 JPEG 像素核对通过；完整菜单包已安装并逐文件回读，安装时原六份配置逐字节不变。用户随后确认 FL7 黑白、原有风格黑白开关、重启保存均正常。重启后的最后一次只读状态查询遇到 USB 管道错误，待重连接口后补读；这一状态与用户已完成的菜单/照片验收分别记录。本次以完整包更新同一个 v0.01，最终状态回读的暂缓情况保留在发布清单。
