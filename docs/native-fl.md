## 快速构建、加载、恢复

使用 Python 3、原有 ARM GNU/QEMU 环境和已经配置好的 UTM/PMCA USB 通道。固件、设置及结果都留在 `.lab/`，不要提交。

```sh
python3 a7m3.py lut-snapshot

python3 research/native_fl.py \
  --snapshot /absolute/path/to/verified-original-settings.bin \
  --avcam "$A7M3_FIRMWARE_ROOT/0700_part_image/dev/nflasha3_unpacked/av-cam.bin" \
  --pmca "$A7M3_PMCA_DIR" \
  --out .lab/native-fl-new

export A7M3_LUT_EXPERIMENT="$PWD/.lab/native-fl-new"
python3 a7m3.py fl-apply --write-device
python3 a7m3.py fl-status
python3 a7m3.py fl-restore --write-device
```

准备包必须从实验前的原厂 LUT 快照构建，不能拿已启用 FL 的快照叠加构建。每次换配方使用新目录。构建自动执行原厂机器码 QEMU 测试；加载前检查源码、配方、输入、ELF、日志及候选设置散列，并核对机身内部版本和四张表的前值。恢复包应始终保留。

`fl-apply` 只写属性 `0x30004`；接口传输完整 1280 字节，本次其中 1115 字节不同，末尾 65 字节不变。其他三张 LUT 必须与原厂备份一致。每次写入前先落盘保存当前完整 BK4 和事务日志；写入失败或回读不一致时尝试恢复原值。未知前值会停止操作，不盲目覆盖。USB 完全中断时仍可能需要重新连接后运行恢复。

## 近似算法与边界

`research/native_fl.py` 使用原有 `recipes/fl-inspired-v0.json`：明暗曲线、色彩矩阵、整体降饱和及绿/青/蓝方向的分色相调整。每个原厂节点先按原厂 SD 分支中的非线性色度坐标展开，再在假设的显示 RGB 模型里计算配方增量，最后压回机内 5×9×9、三平面格式。

色彩空间使用 Rec.709 类 Y/Cb/Cr 与显示 RGB 的实验解释；原厂压缩/展开函数已经执行验证，但整个 ISP 的颜色空间、传递函数和硬件插值尚未测定。它不是精确的 sRGB Cube 到 Sony LUT 转换器。超出 RGB 色域的节点只加配方增量，不把 RGB 裁剪误差写入原厂校准表。

本版混合强度 0.65；每节点相对原厂值的最大增量分别为 8、12、12 个代码单位，最终范围限制为 −64…63。强度零返回逐字节相同的原厂表。没有加入锐化、清晰度、颗粒或光晕，也没有把 RAW 文件当作 RGB 修改。
