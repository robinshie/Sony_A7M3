# r16：拍后正负暗角

开发与验收日期：2026-11-15。r16 已持久写入、完整回读，并经用户冷启动试用和只读状态核对验收。公开版本沿用 v0.01，附件以 r16-vignette 覆盖旧包；本页分别记录临时实拍、持久写入和冷启动结果。

## 操作与范围

进入 MENU → 拍摄设置 1 → 第 14 页 → 创意外观。第三页在「颗粒（拍后）」「光晕（拍后）」之后增加「暗角（拍后）」，最后为保存。范围 −9…+9：负值压暗四角，正值提亮四角，0 关闭。FL、FL2、FL3 各自保存；沿用保存→确认／取消→完成流程。

当前验证范围是全画幅、3:2、6000×4000 JPEG L，编码前处理。暗角不作用于实时取景或 RAW。测试效果时可暂把颗粒与光晕设为 0，以单独观察暗角；升级本身保留已有设置。

新配置为 schema 5，仍长 128 字节。116…118 三个有符号字节分别保存三个风格的暗角，119…123 保留为 0，124…127 为 CRC。旧 schema 4 解码后暗角默认为 0；旧配置在确认保存前不重写。旧 r15 不认识 schema 5，回退需要匹配的旧设置备份。

## 算法和真实帧

`payloads/a7-film-vignette.c` 使用整数椭圆距离和 smoothstep 过渡：中心区域增益不变，向四角平滑变化。−9 的角部增益为 0.25，+9 为 2，0 字节恒等；这是编码 YUV 上的增益，不宣称等同于线性曝光档位。色度以 128 为中心，使用相邻像素平均增益。行填充、画面边界和工作区另有检查。

内核 `a7capvig` 复用已验证的 JPEG 编码前回调、DMM 排他占用和缓存同步；先执行既有颗粒／光晕，再执行暗角。每张开始时原子快照模式及三个强度，过程中不随菜单变化。无效果或关闭时跳过；不符合已确认格式／几何时不写像素。

三档测试与持久候选使用同一份内核二进制。只读加载参数 `diagnostic=1` 依次执行 −9、0、+9 并停止；正常启动省略该参数，默认 0，使用菜单值。升级后必须确认驻留 `diagnostic=0`。

第一轮只有负档成功，第二张 DMM 锁忙退出；记录保留在 `.lab/capture-kernel/1794730182166987000/`，不作为三档通过证据。修正版最多尝试 64 次非阻塞获取，每次失败都恢复中断标志，无睡眠或无限等待；仍失败则停止效果处理，不能绕过占用检查。ARM 测试覆盖短暂竞争、64 次全部失败、两个已观察缓冲区及释放、同步失败路径。

## 三档真实 JPEG 验证

最终诊断目录为 `.lab/capture-kernel/1794730878828623000/`。用户确认三张拍摄和回放正常；回读为完成 3、失败 0，随后回调已停用。三张为 `_DSC1791.JPG`、`_DSC1792.JPG`、`_DSC1793.JPG`，EXIF 均为 1/10 秒、F4、ISO 100。

每张照片对照它自己的编码前样本，四角及中心各 8×8 像素。独立整数参考逐字节核对源图变换；JPEG 有损编码后检查亮度误差：

| 强度 | 结果 | 四角及中心 JPEG 与处理后样本的 RMS 范围 |
|---|---|---:|
| −9 | 四角压暗，中心原样 | 0.000–1.118 |
| 0 | 五处源样本均字节恒等 | 0.515–1.179 |
| +9 | 四角提亮，中心原样 | 0.771–1.244 |

正负档至少两个可见角落的最终 JPEG 显著更接近处理后样本。报告为 `jpeg-vignette-proof.json`，`passed=true`；它证明这次同一二进制的暗角进入直出，不代表逐像素验证整张照片或其他拍摄尺寸。`research/capture_vignette_jpeg_test.py` 保留照片、元数据、源样本和回调记录散列。

## 本轮发现并修复的启动恢复问题

第一次实验后冷启动，用户报告整个「创意外观」入口消失。只读核对证明 r15 模块和语言资源仍是已验收版本，两份用户配置未变。原厂色表实际保留了前一份已确认的 generation 52 / FL；最新配置为 generation 53 / FL3，而两份预览日志都已是 FL3。旧恢复逻辑无法识别仍留在色表中的上一份确认值；再次启动又重复准备已有的只读捕获表，返回 −11。

本轮先备份配置及工作日志，逐字节确认实际三张色表正是 generation 52 生成结果，再通过原有工作日志接口补入该已确认配方，并在锁内重置准备标记，让原启动路径恢复 generation 53。用户随后确认入口及 FL／FL2／FL3 全部恢复。这里只更新了恢复日志，未改用户参数或替换持久模块。恢复证据：

- `.lab/fl-menu-recovery/1794731098201028000/`：文件身份、配置及色表对照。
- `.lab/fl-startup-history-recovery/1794731888495330000/`：日志修复前后备份、写入结果、用户配置未变。
- `.lab/fl-menu-recovery/1794731952624461000/`：恢复后 runtime_ready=1、generation=53、无错误。

r16 的永久修复读取另一配置槽中完整且紧邻的前一代确认值，仅当实际色表逐字节符合该配方时才允许恢复；未知色表、CRC 错误、身份不符仍拒绝。启动重试复用已准备的只读表；发生原生表写入故障时保留 fault，不自动重试写入。

`research/native_boot_recovery_test.py` 执行三份 ARM 夹具：缺少历史识别会在首个断言失败，缺少准备重试修复会在后续断言失败，两项修复齐全才通过。它还模拟后端一次加载失败，核对后续恢复和原参数保留。`film_worklog_harness.c` 覆盖前一槽、断写、非连续代数、错误 CRC 和未知字节拒绝。
