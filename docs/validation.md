# 验证记录

| 场景 | 结果 |
| --- | --- |
| 真机原始分区 | 300 MiB `/usr` 备份完成；每块 CRC 通过。前 217,267,200 字节与原厂 4.04 ext2 内容完全相同。 |
| 离线构建 | 默认标题修改资源记录 `0x4F7E6`、`0x4F7E7`；只有扇区 `0x8e4f` 的 44 字节不同。发布版生成的完整镜像与实机烧录使用的镜像逐字节一致。 |
| ARM 载荷 | 发布版 QEMU 测试覆盖分区读回、备份块与 CRC、拒绝错误原始扇区、写入并读回、恢复并读回。 |
| 真机写入 | 本地实验版在一台 ILCE-7M3 4.04 通过维护接口写入 512 字节，`fsync` 成功并立即回读。 |
| 重启后的真机 | 断开 USB、取电池后再启动，机主确认菜单显示「我的相机／固件实验」。改版扇区和整个简体中文资源经独立 USB 会话回读一致。 |
| QEMU 界面 | 发布版用虚拟键盘测试 38 个分页、语言切换、我的菜单、Fn、Quick Navi、模拟录像和回放。 |
| 恢复 | QEMU 通过。真机保留改版，没有再做一轮真机恢复；发布版整理后的 USB 流程没有再执行真机写入。 |

默认改版的 ext2 部分 SHA‑256：

```text
4b2b43c45f8932e1dcb2b703d6b3bc77d0bedcfb4eec674dd0d635d203067364
```

这个 SHA‑256 只覆盖与官方 ext2 对应的前 217,267,200 字节。完整 300 MiB 镜像还保留备份中其余字节，请以本地 `patch.json` 为准。

## 为什么不替换官方 DAT

使用官方更新包自带的验证公钥做了对照：未改动 FDAT 的 RSA/SHA‑256 签名通过；只改一位并重算外层 CRC 后，原签名验证失败。文件名不影响签名结果。对这台已装 4.04 的机身，未改的 4.04 还在官方 USB 更新协议的头部版本预检阶段返回 `0x0142 Invalid version`；该次对照只送了预检所需头部，没有发送写入指令。Sony 官方 [4.04 更新页面](https://www.sony.com/electronics/support/e-mount-body-ilce-7-series/ilce-7m3/software/00257839) 也将升级起点列为 4.03 或更早。当前工具通过 USB 维护通道写入一个分区扇区，不重新签名或替换官方更新包。
