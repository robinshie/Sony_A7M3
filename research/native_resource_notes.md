# Native UXC expansion acceptance

The original Sony A7M3 4.04 UXC v7 parser accepts the expanded Simplified Chinese
and English locale files generated by `research/native_fl_strings.py`.

`native_resource_fixture.py` executes original ARM Thumb machine code extracted
from the user's local `libObj.so`, pinned to SHA-256
`1117453a969c9dedeb9bf6b006514fd9c2644a79085590a797189df109d64d23`.
It is not another implementation of the string-index parser. The fixture's C
harness calls original functions for header validation, counts, record lookup,
resource IDs and record types. It independently compares the returned strings
and the expected new label bytes.

```sh
PYTHONPATH=research:.lab/research-deps python3 research/native_resource_fixture.py \
  --usr /path/to/nflasha15_unpacked
```

Requires ARM GCC and QEMU. Optional `--before` and `--after` select the deployed
locale directory and generated locale directory. Input files must match the
generator's `proof.json`; generator source hashes must still match as well.
Extracted Sony bytes remain in ignored `.lab/native-resource`.

Result: **91,061 checks passed**.

- Both original and expanded files pass the original UXC v7 header validator.
- Original native count extraction returns 7,582 before and 7,592 after.
- Original native data-base computation advances precisely 40 bytes.
- Every one of 7,582 prior slots in each locale is looked up through original
  mixed short/long-index code. Assigned/unassigned state is unchanged, every old
  resource ID and text type matches, and every old UTF-8 string is byte-identical.
- Chinese has 7,581 assigned prior slots and one unassigned slot; English has
  7,580 assigned prior slots and two unassigned slots.
- All ten appended labels in each locale resolve at `0x0204fd9e..0x0204fda7`
  with the expected native resource ID, string type 7, and exact UTF-8 bytes.
- The old count excludes those added IDs; the new count rejects index 7,592,
  index 8,191 and `0xffffffff`. The native validator rejects altered magic and
  accepts it again after restoration.

The report `.lab/native-resource/report.json` records input and extracted-code
hashes, generator proof hash, fixture source hashes and the run log.

## Exact original entry points

All addresses are relative to `libObj.so`; odd callable addresses select Thumb.

| Operation | Entry point | Relevant behavior |
|---|---:|---|
| UXC header validator | `0x816119` | Compares magic `0x07637875` (`uxc`, version 7) |
| Index type | `0x8159ab` | Low two bits of the index header |
| Count | `0x8159cf` | Low 13 bits of packed index word |
| Index array base | `0x8159db` | Offset from low header byte |
| Data-record base | `0x8159e9` | Index-array base plus packed word-size offset |
| Mixed index offset | `0x8159ff` | Native short/long entry decoding and bounds checks |
| Record pointer lookup | `0x815a7d` | Native index lookup plus native data-record base |
| Record resource ID | `0x8207c7` | Extracts resource ID from record header |
| Record type | `0x5f4451` | Extracts native type from record header |

For string UXC files, pass the whole file to the validator, and `file + 8` to the
index count/base/lookup functions. Record helpers receive the returned record
pointer. The native UXC load path at `0x8161cc` explicitly dispatches to the same
header validator when byte 2 is `c`; the lookup path at `0x8162f0` calls the same
record lookup.

## Scope

This establishes native binary-format and lookup compatibility of this exact
expansion. It does **not** exercise the OS file mapping layer, resource-manager
cache replacement, font glyph availability, line wrapping or LCD rendering.
It is an offline parser component test and performs no USB or camera writes.
